\subsection{Derived indicators}
Definitions of the indicators that are computed rather than read directly from the platform.

\begin{itemize}
\item \textbf{\texttt{passive\_ret\_month} (X / IV).} At the user-month level, defined as \footnote{\textcolor{red}{Up to now we use the return within a natrual month, without adjusting for the submit date.}}
$$\sum_{f}(\text{hold}_{u,f,t-1} \times \text{fund\_ret}_{f,t}) \,/\, \text{portfolio\_m\_prev},$$
 where the numerator is the sum across all funds the user held at the end of month $t-1$ of the per-fund return in month $t$, and the denominator is the previous month's total market value of the portfolio {\color{cyan}(in the dataset, $\text{portfolio\_m\_prev}$ is just the sum of $\text{hold}_{u,f,t-1}$, right?)}. The numerator is the dollar return the user would have earned without trading; dividing by the previous portfolio normalizes it to a ratio in $[-1, 1]$, comparable across users of different portfolio sizes.

\item \textbf{\texttt{realized\_ret\_month} (X / endogenous).} At the user-month level, defined as the sum across all funds of the platform's \texttt{当月累计月收益元} column from the \texttt{invest} table. This is what the platform actually booked into the user's account.

\item \textbf{\texttt{portfolio\_m\_prev}.} Total market value of the portfolio at the end of month $t-1$. Serves as the denominator of \texttt{passive\_ret\_month}.

% \item \textbf{\texttt{cross\_wave\_overflow}.} Indicator equal to 1 if \texttt{submit\_month} $>$ \texttt{wave\_end\_month}. Affects roughly 9.87\% of the 2024q3 sample. Carried into the controls vector.

% \item \textbf{\texttt{age\_outlier}.} Indicator equal to 1 if respondent age $<$ 18 or $>$ 80. Affects 270 rows.

% \item \textbf{\texttt{tenure-1/2/3}.} Three controls computed as $(\text{ref\_date} - \text{reg\_dt}).\text{days} / 365.25$ with \texttt{ref\_date} = 2025-06-30.
\end{itemize}

\subsection{Lessons learned}

\begin{itemize}
\item \textbf{Fund-month panel must be reindexed before any \texttt{shift(1)} lag.} A naive \texttt{shift(1)} on the raw \texttt{invest} panel misaligns at scale: at least $27{,}220$ fund-months jump by exactly one month and $15{,}397$ jump by two or more. The lag must therefore be applied \emph{after} reindexing the (\texttt{uid}, \texttt{fund}) panel to a full monthly grid with missing months filled as zero holdings; a gap larger than one month is treated as a full exit (\texttt{hold\_prev} $=0$ in that gap).

\item \textbf{Questionnaire structure: v1 splits employer versus employee respondents.} \texttt{v1} classifies the respondent (``我是小微经营者'' selects the employer segment); it determines which subsequent questions the respondent is asked. Several indicators have two parallel question versions --- one asked of employers, one asked of employees.

\item \textbf{Platform hard constraints.} Reading and writing data is limited to the four functions listed below.
\begin{itemize}
  \item \texttt{ant\_read\_data}
  \item \texttt{ant\_print\_all}
  \item \texttt{ant\_plot}
  \item \texttt{ant\_write\_data}
\end{itemize}
Output is capped at 50\,KB per code block and 500\,KB per file. \texttt{describe} / \texttt{corr} / \texttt{value\_counts} require at least 100 input rows; for smaller tables, use \texttt{describe\_by\_discrete} on the large-table aggregate or \texttt{unique} on a Series. Figures are bounded to 3--12 inches and 50--150 DPI. \texttt{try-except} is not permitted.

\end{itemize}

\subsection{Current SME-owner reduced form}

This section summarizes the real-data platform run of the SME-owner reduced-form script, \texttt{01\_sme\_expectations\_rf.py}.

\begin{itemize}
\item The run uses \texttt{ANSWER\_SECONDS\_MIN = 120}: respondents with observed answer time below 120 seconds are excluded, while missing answer time is retained.
\item The sample is restricted to SME owners with positive beginning portfolio holdings and nonmissing passive returns.
\item The analysis is reduced form: it asks whether predetermined passive portfolio returns move expectations.
\item The key empirical result is a \textcolor{red}{broad null}. None of the 11 expectation outcomes is significant at the 5\% level; \texttt{exp\_price} is the closest result ($p=0.0774$).
\end{itemize}

\paragraph{Specification.}
\[
Y_{iw}
= \beta \cdot \texttt{shock\_ret\_rate\_pp}_{iw}
+ \alpha_w
+ \gamma_{c(iw)}
+ \bm{x}_{iw}'\delta
+ \varepsilon_{iw}.
\]

\begin{itemize}
\item $Y_{iw}$ is one of 11 SME-owner expectation outcomes.
\item \texttt{shock\_ret\_rate\_pp} is the passive mutual-fund return in percentage points.
\item $\alpha_w$ are wave fixed effects.
\item $\gamma_{c(iw)}$ are portfolio-cell fixed effects.
\item $\bm{x}_{iw}$ contains four predetermined traits: age, college indicator, firm age, and company-registration indicator. {\color{cyan}[add \texttt{female} and \texttt{employment size} as well.]}
\item Standard errors use HC1.

\subsection{CSMAR shock and control inputs}

The fund-level inputs are built outside the Ant platform from the CSMAR fund files.

\begin{itemize}
\item The merge key is \texttt{fund\_code} $\times$ \texttt{wave}. \texttt{fund\_code} is the six-digit CSMAR \texttt{TradeCode}, normalized to match the Ant holding-table field \texttt{基金代码}.\footnote{Normalization is constructed by treating it as a string, stripping whitespace, removing any trailing \texttt{.0}, and left-padding numeric codes to six digits \textcolor{red}{strings}.}
% \item \texttt{shock\_panel.csv} is the formal shock input. It is a fund $\times$ wave table.
% \item \texttt{ctrl\_monthly\_panel.csv} is the formal control input. It is a fund $\times$ wave $\times$ historical-month table.
\end{itemize}

\paragraph{Shock construction.}
For fund $j$ and wave $w$, the CSMAR script computes a short-window return from cumulative NAV:
\[
r^{shock}_{jw}
= \frac{\text{AccNAV}_{j,\text{end}(w)}}{\text{AccNAV}_{j,\text{baseline}(w)}} - 1.
\]

\begin{itemize}
\item The baseline is the latest valid cumulative NAV on or before the day before the shock window starts. {\color{cyan}[i.e., end of last month]}
\item The end value is the latest valid cumulative NAV inside the wave-specific shock window.
\item The uploaded variable \texttt{shock\_ret\_rate\_pp} equals $100 \times r^{shock}_{jw}$.
\item A fund is usable when return is nonmissing, the return is based on cumulative NAV, the window is \textcolor{red}{sufficiently complete}\footnote{Details mentioned below in ``Trading-day".}, and the return is not extreme.
\item Missing or unusable fund returns are not recoded as zero.
\end{itemize}

\paragraph{Trading-day and quality filters.}
\begin{itemize}
\item Trading days are \textcolor{red}{inferred} from CSMAR daily NAV coverage, rather than from a generic business-day calendar.
\item A date is treated as a trading day when at least 1{,}000 funds report nonmissing cumulative NAV and the count reaches at least 20\% of the maximum daily disclosure count. {\color{cyan}[That's an important technical issue. Let's discuss.]}
\item This rule drops holidays (e.g., Mid-Autumn Festival) and weekend dates with only a small number of special fund records.
\item Completeness is defined as valid NAV dates divided by inferred trading days in the window.
\item The current threshold is \texttt{complete\_ratio >= 0.80}.
\item The extreme-return flag is \texttt{|shock\_ret\_rate| > 0.20}; almost all funds pass this filter in the current output.
\end{itemize}

\paragraph{User-level passive shock.}
After upload, the Ant-platform script merges \texttt{shock\_panel.csv} to beginning holdings and constructs
\[
\texttt{shock\_ret\_rate\_pp}_{iw}
=
\frac{\sum_j H_{ij,w-1}\,\texttt{shock\_ret\_rate\_pp}_{jw}
      \cdot \mathbf{1}\{\texttt{shock\_usable}_{jw}=1\}}
     {\sum_j H_{ij,w-1}}.
\]

{\color{cyan}[if not unsale, should this fund be excluded from denominator as well?]}
The denominator is the beginning portfolio size. The script also reports return coverage, so incomplete shock coverage can be diagnosed separately from the realized value of \texttt{shock\_ret\_rate\_pp}.

\paragraph{Control construction.}
The control input keeps monthly fund returns rather than pre-aggregated fund-level means and standard deviations:
\[
r^{H}_{ijmw}
= \frac{H_{ij,w-1} \cdot \texttt{ctrl\_monthly\_ret}_{jmw}}
        {\sum_k H_{ik,w-1}}.
\]
The platform script first sums these weighted fund returns within each user $\times$ historical month to obtain a fixed-portfolio monthly return. It then computes:
\[
\texttt{expected\_ret\_12m}_{iw}
= \frac{1}{12}\sum_m R^H_{imw},
\qquad
\texttt{portfolio\_risk\_12m}_{iw}
= \operatorname{sd}_m(R^H_{imw}).
\]
This is the Xiaohan-note portfolio-control口径: risk is the standard deviation of the fixed portfolio's historical monthly return series, not a weighted average of individual fund risks.

\paragraph{Shock and control aggregation.}

\begin{itemize}
\item \sout{Holdings are taken from the end-of-previous-window snapshot specified in the script.}  Holdings are measured at \textcolor{red}{the month-end} before each shock window
(e.g., 2024-08 month-end holdings for the 2024q3 shock window).
\item Fund-level shocks are aggregated with holding amounts as weights.
\item Historical controls use the monthly control panel and the same beginning-portfolio weights.
\item Return coverage is essentially complete in every wave; control coverage is high but not literally complete for all users.
\end{itemize}

\paragraph{Sample and cells.}
\begin{itemize}
\item Starting from 59{,}009 survey rows, the SME-owner filter leaves 36{,}153 rows; the answer-time filter leaves 28{,}144 rows; positive beginning portfolio leaves 15{,}807 rows.

\paragraph{Industry and employee fields.}

\item Because employee count is coarse and categorical, a grouped employment-size fixed effect is preferable to a continuous control for the next regression run. Any nonmissing raw employee answer not covered by the current mapping can be retained as an \texttt{emp\_unmapped} FE level rather than dropping the observation.
\end{itemize}

\paragraph{Conditional variation and balance.}
