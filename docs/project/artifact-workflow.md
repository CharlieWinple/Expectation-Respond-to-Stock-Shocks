# 结果与文件管理工作流

本规则适用于本仓库。外部 CSMAR 数据工程保留原有路径，本仓库只记录其入口，
不跨工程移动原始数据。不新增日期版本文件夹；代码版本由 Git 管理。

## 1. 接收与登记

- 按分析主题与实际运行编号建立 `outputs/platform_runs/<topic>/<run>/`。
  没有平台编号时依次使用 `run_001`、`run_002`，不同提交不可覆盖。
- 原始 PDF 放 `source/`，保留收到时的文件名。截图放 `screenshots/`。
- 登记接收日、脚本版本/commit、配置、报告页码、文件 SHA256、证据来源
  （后台真实数据 / 在线模拟 / 未确认）。缺失信息标为未确认，不自行推断。
- `docs/project/results/README.md` 提供运行索引；本地清单记录文件级路径和哈希。

## 2. 读取与核验

- 先检查标题、配置、BEGIN/END、页码连续性、截断与数据来源，再读取表格。
- 有文本层则提取文本；扫描报告渲染到 `pages/`，OCR 放 `ocr/`。
  OCR 只是辅助检索，正式数字应对照原图核实。
- 核对样本数加总、模型/结果行数、重复锚点与单位。记录缺页、未识别内容、
  已核验范围；成功结束标记本身不证明报告完整。
- 校对后的 JSON/CSV 放 `verified/`；派生图放 `figures/`；一次性脚本与中间
  文件放 `scratch/`。已有报告目录中的平铺文件视为历史布局，不假定全部已核验。

## 3. 保存与形成结论

- 每次平台运行更新 `docs/project/run-log.md`；完整解读放
  `docs/project/results/<run>.md`，可复用结论进入 `findings.md`。
- 解读文档可包含解释所必需的精选表格；完整数值导出仅本地保留。
- 用户要求保存重要结论时写入 `docs/notes/note-cache.md`；只有明确要求整理
  Notes 时才转入 `Notes_Yanpeng.tex`，核验后移除已转移缓存。
- `docs/project/status.md` 只保留当前状态和下一步；历史状态放
  `docs/project/history/`。README 只作导航，不复制运行日志。

## 4. 归档与清理

- 被新报告取代的部分报告仍保留原始证据，索引标为历史/部分报告。
  不因结果旧、显著性低或识别不理想而删除。
- 旧数据面板放 `data/archive/`；截图旧版本保留在既有本地 archive 中。
- 只有逐字节一致且用途可替代的副本，或可重建缓存，才可删除。清理前保存
  清单和 SHA256；有人工标注、来源不明或无法重建的文件保留。
- Notes 的 PDF 与插图保留本地原路径以兼容 LaTeX；编译检查放
  `outputs/note_build/`，通用临时文件放 `tmp/`。这些目录及产物不提交。
- 本地忽略文件没有 Git 备份。原始报告、核实数字、数据和 Notes 插图应纳入
  独立的文件备份，不能把 Git 当作完整研究档案。

## 5. Git 提交边界

同步代码、测试、Notes 源稿/缓存、说明、方法、运行记录、结果解读和 schema。
不提交原始数据、完整数值结果、PDF/截图/OCR、生成图片、归档和临时文件。
文件已经被 Git 跟踪时，新增 ignore 规则不会生效，需仅从索引解除跟踪，
本地文件保留。此操作不清除旧提交中的历史内容；本次不重写 Git 历史。

提交前检查 `git status`、`git diff --check`、`git ls-files` 与
`git check-ignore`。脚本有路径变更时做语法检查并运行受影响的本地操作；
不把本地检查视为平台真实数据证据。相关脚本与结果说明同一次提交，
不混入未审阅的其他研究修改。
